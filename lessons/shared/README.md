# Shared modules (`lessons/shared/`)

[Deutsch](README.de.md)

Several lessons share these files. You do not need to read them to understand the lessons; the lessons explain everything important themselves. This page says what each file is for, in case you want to look something up.

**`config.ts`** reads the settings from `.env` (LM Studio server, model names, Burp, Qdrant address, facade port, the optional switches `ALL_DOCUMENTS` and `SHOW_THINKING`, read with `optionalBooleanEnv` (empty, `true` or `false`, also `1`/`0`, `yes`/`no`; `settings.showThinking` for the latter); older keys report themselves with a hint at the new name) and validates them. Every lesson uses it. A setting is only validated when a program needs it; if it is missing, the program prints a message and exits. Not needed to understand the lessons, unless you wonder where `remoteModel.name` or `baseURL` come from.

**`paths.ts`** defines where the repo root and the `content/` and `indexes/` folders are. File paths in the code (certificate, chunks, indexes) are resolved from there, so the programs work from any working directory. Only `.env` is loaded by Node relative to the working directory. `proxy.ts` uses it from Lesson 01, Part 3; from Lesson 04, `content/` and `indexes/` join in. Not needed to understand the lessons.

**`proxy.ts`** builds the proxy agent from `BURP_PROXY_URL` (and `BURP_CA_CERT`) that routes requests through Burp (`getBurpDispatcher`). `useBurpIfConfigured()` makes it the global dispatcher when an address is set, and is the one line that the programs from Lesson 02 onward call for this. Lesson 01, Part 3 shows the long form with `setGlobalDispatcher`. If no proxy address is set, the agent is `undefined` and the programs connect directly. The file also checks whether Burp is listening (`burpProxyReachable`) and aborts with instructions if an HTTPS address is supposed to go through Burp but the certificate is missing (`requireBurpCertificate`, used in Lesson 02, Part 2). First needed in Lesson 01, Part 3, where it is explained. Not needed to understand the lessons, unless you want to know how the CA certificate is wired in.

**`logging.ts`** prints log lines with a timestamp (`log`), wraps calls with start, end and duration messages (`logInvocation`), logs HTTP requests to the facade (`logHttpRequests`) and redacts API keys in error messages (`errorDetails`), prints errors as a line with the cause (`logError`), detects cancellations (`isAbortError`) and, with `DEBUG` set, appends the stack traces (`debugErrorDetails`). In use from Lesson 01, Part 1. The timestamps help you match the output against Burp's HTTP history. Not needed to understand the lessons.

**`diagnostics.ts`** checks at startup whether the model server responds and, for programs using Burp, first whether Burp is listening and the route through Burp works. A failure ends the program with an English message that tells you what to check. Used from Lesson 01, Part 2. Not needed to understand the lessons, except when troubleshooting: the log lines there tell you whether the server or Burp is the problem.

**`startup.ts`** contains `runMain`, the wrapper in which every program puts its work. Errors appear as a one-line English message with a short cause (`<what failed> – Cause: <why>`) instead of a long stack trace and end the program with exit code 1. With `DEBUG=1` (e.g. `DEBUG=1 npm run l01:1`; Windows: see the [root README](../../README.md)) the stack trace is added. Errors that were already logged are not printed twice. A cancellation by you does not count as an error (log: `Request cancelled.`). Used from Lesson 01, Part 1. Not needed to understand the lessons.

**`facade.ts`** reads the version and files of the `ollama-api-facade-js` package, including its own Express copy. `server.ts` and `stream.ts` use it to check the version, so that a reinstall does not silently change the behavior. Used indirectly from Lesson 01, Part 2. Not needed to understand the lessons.

**`server.ts`** sets up the Ollama facade: JSON parser (`prepareFacade`, which also rejects requests with a foreign Host header with 403, as protection against DNS rebinding: a foreign web page should not reach the facade via its own domain name; allowed are `localhost`, IP addresses, `host.docker.internal`, `host.containers.internal` and the name from `FACADE_HOST`), error responses (`logHttpErrors`; a cancellation in Open WebUI is only logged as INFO) and the start on `FACADE_HOST`/`FACADE_PORT` (default `127.0.0.1` and `11435`) with a hint at the address for Open WebUI (`listenWithLogging`). First needed in Lesson 01, Part 2. Not needed to understand the lessons, unless you get the message that the port is in use.

**`stream.ts`** sends the model's answer as a stream (piece by piece) to Open WebUI and provides a signal that fires on a cancellation in Open WebUI. Its option `footer` appends a fixed text after the answer (the source list of Lessons 02 and 07). Before sending, unless `SHOW_THINKING=true`, it removes the thinking of reasoning models with `withoutThinking`, so Open WebUI only ever shows the answer (with `SHOW_THINKING=true` it sends the thinking as a `<think>` block, which Open WebUI shows collapsed); this also works when a tag arrives split across two stream pieces. `printModelStream` writes a model stream to the console the same way (Lessons 01 and 02). The server sends the thinking in a separate response field (`reasoning`, some servers `reasoning_content`), not as `<think>` in the text; LangChain drops that field, so the chat clients set `__includeRawResponse: true`, and `stream.ts` and `text.ts` read it from the raw response. Used from Lesson 01, Part 2. `stream.ts` accesses a private field of the facade library and therefore only works with the version pinned in `package.json`. Not needed to understand the lessons.

**`abort.ts`** contains `abortable`: it waits for a promise but gives up as soon as the signal fires (used by `stream.ts` and Lesson 07). Used from Lesson 01, Part 2. Not needed to understand the lessons.

**`messages.ts`** converts the facade's messages into plain `{ role, content }` objects (`toPlainMessages`) and splits off system prompts that someone set in Open WebUI (`splitSystemPrompts`). `toPlainMessages` from Lesson 01, Part 2, `splitSystemPrompts` from Lesson 02, Part 1. `withLastUserContext` inserts context (web page, hits) before the text of the last user message so that the roles stay alternating (Lesson 02, Part 2). `isOpenWebUITask` detects helper requests from Open WebUI (titles, tags; they start with `### Task:`), for which Lesson 02, Part 2 fetches no web page and Lesson 07 does not search. They get a reduced system prompt (guardrail against instructions in the material and language rule, but not the "only from the sources" rule, which would break the JSON for titles and tags); so a leading `### Task:` bypasses nothing important. Not needed to understand the lessons, unless you want to know why there may only be one system message.

**`embeddings.ts`** contains the E5 model with its prefixes and its token limit (`e5Model`), cosine similarity (`cosineSimilarity`) and a check that the server returned exactly one vector per text (`assertVectorCount`). `createEmbeddings` builds the embedding client (floating-point numbers, no retries, line breaks are preserved). `embeddingQuery` prepends `query: ` to a question and truncates it to `QUERY_CHARACTER_LIMIT` characters so that it fits the 512-token limit. The limit is computed with `CHARACTERS_PER_TOKEN` (2.5 characters per token, a deliberately cautious estimate) and `SPECIAL_TOKEN_RESERVE` (2 tokens for start and end, which E5 puts around every text). First used in Lesson 03. Cosine similarity is part of the material of Lesson 03, but reading its calculation is not necessary.

**`index.ts`** reads and writes the index files under `indexes/` (`indexFileFor`, `readIndex`, `writeIndex`) and contains the ranking: `rankEntries` sorts the entries by cosine similarity to the question and keeps the best `DEFAULT_TOP_K` (3; Lessons 05 to 08 set their own values per file), `uniqueChunks` makes each chunk count only once in the question index. It also holds the zod schema of the index entries, the shared embedding client (`embeddings`) and `INTERNAL_DOCUMENTS`, the list of documents that Lessons 05 and 07 and Lesson 08, Parts 2, 3 and 5 filter out of the search (access group `internal`; Lesson 06 deliberately searches unfiltered); `isPublicChunk` is the shared rule for that. Smaller pieces: `INDEX_FORMAT_VERSION` (version of the index file), `Strategy` and `indexCommands` (the four strategies and the npm script that creates their index), `chunkKey` (document plus position as the identity of a chunk), `requireEntries` (throws on an empty list), `indexLoadError` (the error message of Lessons 05 to 08 when an index is missing), `HEADING_SEPARATOR` (separator for the heading path) and `sectionPath` (the heading path without the document title, for display). Lesson 04 writes the indexes, Lessons 05 to 08 read them (Lesson 06 loads them into Qdrant), which is why the code lives here; the parts of Lesson 04 import it directly from `shared/index.ts`. Used from Lesson 04, Part 1. Not needed to understand the lessons, unless you want to know how Lessons 05 to 07 load the index.

**`text.ts`** contains `modelText` (the answer of a model response without its thinking; with `SHOW_THINKING=true` the thinking is put in front as `<think>…</think>`) and `modelReasoning` (the thinking from the separate response field). `stripThinking` removes `<think>…</think>` blocks, an unfinished block, or everything before a lone `</think>` from finished text, so that only the answer is shown, checked or kept in the chat history; with `SHOW_THINKING=true` it returns the text unchanged; used for all model answers that do not go through `stream.ts` (e.g. Lesson 02, Part 3 and Lesson 08). It also contains `stripJsonFence`: small models like to wrap JSON in a Markdown code block, and this function removes that wrapper so that `JSON.parse` can read the content. Used from Lesson 04, Part 4 (generated questions) and in Lessons 06 and 07 (multi-query, reranking) and Lesson 08, Parts 2 and 3 (the judge's verdict). It removes the thinking first (`stripThinking`). It also contains `formatSourceList`, which builds the source list (``- `[n] source · heading path` ``) that the code appends to answers in Lessons 02 and 07: each entry is one inline code span, which Open WebUI shows literally, so a heading cannot become a link, image or LaTeX formula (OWASP LLM05). `stripSourceList` (or `withoutSourceLists` for a whole conversation) removes that list from earlier assistant messages before the conversation goes to the model, so it cannot copy an old list or cite stale numbers. Not needed to understand the lessons.
